# DEF-001: Fresh git clone fails setup — requirements.txt, server/, training/, scripts/ missing from HEAD

- **Defect ID**: DEF-001
- **Title**: Fresh clone from git repository fails setup due to uncommitted release artifacts in git HEAD
- **Severity**: S1 (Blocker)
- **Priority**: P1 (Immediate)
- **Component**: Deployment / Build / Git Repository
- **Commit Hash Tested**: `1bb20365573883f0d41a0e4f310d737a95a015b0`
- **Environment**: macOS 27.2 (arm64), Python 3.12.16, Node.js v26.12.1

## Steps to Reproduce
1. In an isolated directory, clone the repository at `HEAD`:
   `git clone . /tmp/swarmrl_fresh_clone && cd /tmp/swarmrl_fresh_clone`
2. Follow the README Quickstart instruction 1:
   `pip install -r requirements.txt`

## Expected Result
`requirements.txt` is present in the repository root, and pip proceeds to install dependencies.

## Actual Result
Command immediately exits with code 1:
```text
ERROR: Could not open requirements file: [Errno 2] No such file or directory: 'requirements.txt'
```
Furthermore, the `server/`, `training/`, and `scripts/` directories documented in the README and repo layout do not exist in the committed git tree at `HEAD`. They exist only as unstaged/untracked files in the developer workspace.

## Frequency
Always (100% reproducible on any fresh clone).

## Suspected Area
The developers modified files and authored new modules in their local working tree but failed to commit them to `origin/main` (`1bb20365573883f0d41a0e4f310d737a95a015b0`).

## Workaround
The user/tester must manually copy or track the uncommitted working directory tree from `/Users/vedantdubey_20/Downloads/SwarRL`.
