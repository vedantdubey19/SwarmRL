# DEF-002: Duplicate and legacy root modules violate single source of truth

- **Defect ID**: DEF-002
- **Title**: Leftover duplicate and legacy root files create competing entry points and dead code
- **Severity**: S2 (Major)
- **Priority**: P2 (High)
- **Component**: Architecture / Repository Hygiene
- **Commit Hash Tested**: `1bb20365573883f0d41a0e4f310d737a95a015b0`
- **Environment**: macOS 27.2 (arm64)

## Steps to Reproduce
1. Inspect the repository root:
   `ls *.py *.js`
2. Observe multiple competing entry points and mock feeds:
   - Root `server.js` vs `server/server.js`
   - Root `schema.js` vs `server/schema.json`
   - Root `train.py` vs `training/train.py`
   - Root `mock-env-feed.js` (dead mock data generator in repo)
   - Root `train_audit_trial1.py` and `train_audit_trial2.py`
   - Root loose test scripts (`validate-50-agents.js`, `test-client.js`, `bad-payload-test.js`, etc.)

## Expected Result
Per Standing Rules:
"One source of truth for each thing: one env module, one reward module, one protocol schema, one config for the WebSocket endpoint. No second copies, no stub files left behind. No mock data in the live path."
The repo layout should cleanly maintain only `env.py`, `sensors/`, `training/`, `server/`, `frontend/`, `scripts/`, `tests/`, `docs/`.

## Actual Result
Competing root files create severe confusion on which script runs the relay or training. For instance, executing `node server.js` executes the old legacy relay instead of `server/server.js`.

## Frequency
Always.

## Workaround
Users must strictly invoke files under `server/server.js` and `training/train.py`, ignoring the root `.js` and `train*.py` files.
