# SwarmRL System Interface Contract & Architecture Review

## Overview
This document defines the interface contracts, data shapes, communication protocols, and risk analyses across all sub-teams for SwarmRL (50-agent drone swarm search-and-rescue system).

## Sub-Team Responsibilities
* **Environment & Physics Engine:** Venkatesh / Vedant (PettingZoo `ParallelEnv`, drone kinematics, collision checking, arena boundaries)
* **Sensors & Exploration:** Saju (`ConeSensor`, `ExplorationMap`, FoV raycasting)
* **Reward Shaping & Multi-Agent Metrics:** Saju / Humera (`calculate_reward`, team vs individual credit attribution)
* **RLlib MAPPO Training Pipeline:** Humera (`MultiAgentEnv`, centralized critic $V(s)$, actor $\pi(a_i|o_i)$)
* **WebSocket Streaming Bridge:** Arya (Node.js / Python WebSocket relay, publisher/subscriber protocol)
* **3D Visualization & Visual Overlays:** Dhruv (React-Three-Fiber, Three.js drone meshes, sensor cones, coverage heatmaps)

---

## Shared Interface Contracts & Risk Matrix

| Interface | Owners | Spec Needed | Risk If Unclear |
|---|---|---|---|
| **Agent Observation Space** | Sensors (Saju) $\leftrightarrow$ Env & RLlib MAPPO (Venkatesh / Humera / Vedant) | **Data Shape & Type:** 1D `Box(low=-inf, high=inf, shape=(81,), dtype=np.float32)`.<br>**Composition & Ordering:** Drone self-state (`[x, y, z, vx, vy, vz, cos(yaw), sin(yaw)]`) + sorted K-Nearest Neighbors (K=6, 24 dims) + Saju's `vectorize()` ($8 \times 3 = 24$ dims: `[type_id, dist/range, angle/pi]`) + local 5x5 exploration grid slice (25 dims).<br>**Object Type IDs:** `{'target': 1.0, 'obstacle': 2.0, 'drone': 3.0, 'empty': 0.0}`. | **CRITICAL AMBIGUITY:** Observation vector length or component ordering mismatch will crash RLlib policy initialization (`ValueError: shape mismatch`). Inconsistent normalization (e.g. angle in $[0, \pi]$ vs $[-\pi, \pi]$, distance raw meters vs $[0, 1]$) will destabilize MAPPO value baseline and gradient updates. |
| **Local Perception Query** | PettingZoo Env Engine (Venkatesh / Vedant) $\leftrightarrow$ Sensors (Saju) | **Signature:** `ConeSensor.detect(position: np.ndarray, heading: float, objects: list[dict]) -> list[dict]`.<br>**Object Schema:** `list[{"id": str, "position": np.ndarray[3], "type": str}]`.<br>**Coordinate Frame:** Position `[x, y, z]` (ground: X-Z, elevation: Y). Heading in radians where $0 = [1, 0, 0]$ ($+X$). | **HIGH INTEGRATION BUG:** Saju hardcodes 2D planar heading $[ \cos(h), 0, \sin(h) ]$ ignoring 3D pitch/roll. If the physics engine includes drone banking/pitching, sensor detection ignores altitude tilt. Passing 50 drones $\times$ all objects as Python `list[dict]` creates an $O(N^2)$ Python loop ($2,500$ checks/step), bottlenecking RLlib rollout workers by $>10\times$. |
| **Exploration Tracking & Reward Credit Attribution** | Sensors & Rewards (Saju) $\leftrightarrow$ PettingZoo Env / RLlib (Venkatesh / Humera) | **Signature:** `calculate_reward(agent_id: str, new_cells: int, previously_explored: bool, target_found: bool, drone_collision: bool, obstacle_collision: bool, boundary_violation: bool, config: RewardConfig) -> tuple[float, dict]`.<br>**Grid Attribution:** Must redefine `ExplorationMap.mark_explored(positions)` to return per-agent cell counts `dict[str, int]`, not aggregate swarm sum. | **CRITICAL FLAW IN CODEBASE:** `ExplorationMap.mark_explored` takes all drone positions at once and returns a single integer. If evaluated sequentially per drone, leading drones receive positive rewards while trailing drones in formation get zero new cells and get hit with `-0.1` `repeated_area` penalty. Also, `calculate_reward()` returns `(float, dict)`, whereas PettingZoo `step()` requires `rewards: dict[str, float]`. |
| **Centralized Critic Global State (`env.state()`)** | PettingZoo Env (Venkatesh / Vedant) $\leftrightarrow$ RLlib MAPPO (Humera) | **Data Shape:** 1D `np.ndarray` of fixed shape (e.g., `(50 * agent_feat_dim + grid_flat_dim,)`, `float32`).<br>**Contract:** Deterministic agent indexing sorted strictly by `agent_id` (`drone_0` through `drone_49`). Masking vector for disabled/crashed drones. | **CRITICAL ARCHITECTURAL BUG:** If agent state ordering in the centralized critic changes across steps, or if crashed drones are omitted rather than zero-masked, MAPPO's global state value function $V(s)$ receives shuffled feature representations, destroying value estimation convergence. |
| **Multi-Agent Action Space & Termination Semantics** | RLlib MAPPO (Humera) $\leftrightarrow$ PettingZoo Env (Venkatesh / Vedant) | **Action Space:** `gymnasium.spaces.Box(low=-1.0, high=1.0, shape=(4,), dtype=np.float32)` representing $[\Delta v_x, \Delta v_y, \Delta v_z, \Delta \text{yaw}]$.<br>**Termination Flags:** Must lock whether `drone_collision (-100.0)` terminates only the collided drone (`terminateds[agent_id] = True`) or terminates the entire episode (`terminateds["__all__"] = True`). | Policy execution failure: If RLlib outputs continuous velocity deltas but Env expects discrete waypoints/steps, actions will silently fail or crash. If single-agent death terminates `__all__`, 50-drone training episodes will abort prematurely every few steps. |
| **Python Simulation $\to$ WebSocket Streaming Protocol** | Python Bridge / Env (Vedant / Venkatesh) $\leftrightarrow$ WebSocket Server (Arya) | **Transport & Role:** Python runs as WebSocket client publisher to `ws://localhost:8080`.<br>**Handshake:** `{ "type": "handshake", "role": "publisher" | "subscriber" }`.<br>**Telemetry Packet Schema:**<br>`{ "type": "frame", "step": int, "timestamp": float, "drones": [ { "id": int, "pos": [x, y, z], "rot": [qx, qy, qz, qw], "status": "active"|"crashed" } ], "targets": [ { "id": int, "pos": [x, y, z], "found": bool } ] }`. | **CRITICAL INTEGRATION GAP:** Arya's `server.js` currently treats all incoming connections identically, only runs `console.log(data)`, and lacks any pub/sub broadcast mechanism to downstream clients. Streaming 50 drone states at 20–30 Hz via naive unbuffered JSON strings will block Node's event loop and exhaust memory. |
| **Spatial Coordinate Frame & Heading Convention** | Env & Sensors (Saju / Venkatesh) $\leftrightarrow$ React-Three-Fiber Frontend (Dhruv) | **Coordinate System:** Three.js Y-Up Right-Handed: $+Y = \text{up}$, $+X = \text{right}$, $+Z = \text{forward/depth}$.<br>**World Extents:** World bounds `[-50.0, 50.0]` on X and Z (matching Saju's `world_size = (100, 100)` centered at origin).<br>**Rotation Format:** Unit quaternions `[qx, qy, qz, qw]` or locked Euler convention (Yaw around Y, pitch around X, roll around Z). | **SEVERE VISUAL BUG:** Saju treats heading $0$ as $[1, 0, 0]$ ($+X$) in X-Z space, while Three.js default mesh forward is $[0, 0, -1]$ or $[0, 0, 1]$. Drones will visually fly perpendicular/backwards to their velocity vector. Swapping Y and Z (common between aerospace Z-up and Three.js Y-up) will project drones vertically into the ground plane. |
| **Exploration Grid / Heatmap Streaming** | Sensors / Python Bridge (Saju / Arya) $\leftrightarrow$ R3F Visual Overlays (Dhruv) | **Wire Format:** Either sparse delta updates `{ "type": "grid_delta", "cells": [ [col, row], ... ] }` or a packed binary bitmask / Uint8Array base64 string.<br>**Resolution:** $50 \times 50$ array ($2.0$ unit cell size). | Transmitting a raw $50 \times 50$ boolean array ($2,500$ JSON floats) at 30 FPS generates $\sim 75\text{ KB/s}$ of redundant JSON serialization overhead, causing UI stutter, dropped WebSocket frames, and WebGL rendering lag in Three.js. |
| **Sensor Frustum / Cone Visualization Overlay** | Sensors (Saju) $\leftrightarrow$ R3F Visual Overlays (Dhruv) | **Parameters:** `range: 20.0`, `field_of_view: 1.570796` (90°).<br>**Geometry Representation:** 3D cone mesh originating at drone position oriented along heading vector.<br>**Target Detection Events:** Streaming payload includes `detections: [ { "drone_id": int, "target_id": int } ]` to render dynamic visual highlight lines/rays. | Frontend and backend detection mismatch: If R3F renders a 3D cone but Saju's backend only computes horizontal dot products on 2D planes, targets visually inside the 3D cone will fail to be detected, leading users to believe the sensor pipeline is bugged. |
| **Interactive Simulation Control Uplink** | R3F Frontend UI (Dhruv) $\leftrightarrow$ WebSocket Server (Arya) $\leftrightarrow$ Env Runner (Vedant) | **Command Message Schema:**<br>`{ "type": "command", "action": "pause" | "play" | "step" | "reset" | "set_rate", "rate_multiplier": float }`.<br>**Ack Message:** `{ "type": "command_ack", "action": str, "status": "ok" | "error" }`. | Without bidirectional command schema and acknowledgment, frontend UI controls (Play/Pause/Reset) either cause unhandled JSON crashes on the Node server or race conditions with the Python stepping thread. |
